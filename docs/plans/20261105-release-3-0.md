# Release 3.0.0

## Overview
- Ship the new app as version 3.0.0. An Inno Setup 7 script installs the self-contained win-x64 publish folder over a
  2.0.x install, in place, with the same `AppId`. Setup empties the program folder before the copy and removes the
  2.0.x shortcuts, so no 2.0.x file outlives the upgrade.
- A release workflow on a `vX.Y.Z` tag builds, tests, publishes, builds the installer and attaches it to a GitHub
  release whose body is the tag annotation. The workflow is written and statically checked here; it never runs in
  this slice.
- The version is 3.0.0 in `SpectrumVisualizer/Directory.Build.props`.
- The old WinForms app, its MSTest project, `SpectrumVisualizer.sln` and the old installer script are deleted; CI,
  `CLAUDE.md`, the README and `docs/architecture` lose every mention of them.
- Firmware compatibility: the app reads only the OptoskyProj#20 frame, the 2.0.x app cannot read it, and the frame has
  no version byte. The `BoardNotResponding` and `UnrecognisedData` remedy texts (English and Russian) name old board
  firmware as a cause. The README and the release-notes draft say "flash the board firmware delivered with this
  release first, then install". Semiteq distributes that firmware together with the release; no operator text points
  at the private OptoskyProj repository.
- The README is rewritten for operators: install, board firmware, how to use, where data and logs live. The developer
  sections stay below them.
- Scope guard: no feature work. The run does not tag, publish or push. Untracked folders on disk (`ComPortPopulator/`,
  `SprctrumVisualizer/`, and the ignored `bin/` and `obj/` of the old projects) are not touched.

## Solution Overview
- **Packaging follows SemiPlot**: an Inno Setup script under `Installer/` with paths relative to the script, fed by
  the self-contained publish folder that `Directory.Build.props:33-38` already defines, and a release workflow shaped
  like SemiPlot's. The script keeps the 2.0.x `AppId`, so Windows sees one product and setup upgrades in place.
- **Decisions:**
  - The `AppId` is the 2.0.x one, `{02EA7FE7-4B06-4B9C-93ED-2B49AE013EAA}`. Setup reuses the previous folder and the
    previous desktop-task choice, and the uninstall entry stays one entry.
  - `[InstallDelete]` empties the program folder with `Type: filesandordirs; Name: "{app}\*"` before `[Files]` copies.
    The 2.0.x payload is unknown and may differ per site, so a list of named files cannot be complete. The folder is
    the app's own folder under Program Files; 2.0.x never wrote data or settings there, and 3.0.0 keeps its data and
    logs under `%LOCALAPPDATA%`. An operator who chose a custom folder holding other files loses them; the app has
    always installed into its own folder by default (`inno_setup.iss:18`), and that cost is accepted.
  - `[InstallDelete]` also deletes the 2.0.x Start menu and desktop shortcuts. `[Icons]` recreates the Start menu one
    and, when the task is checked, the desktop one.
  - The Start menu shortcut is `{autoprograms}\SpectrumVisualizer` with `DisableProgramGroupPage=yes`, the same path
    as the 2.0.x shortcut. SemiPlot's `{group}` is not used. Shortcuts carry no parameters: the app has no launch
    keys. The task name `desktopicon` stays, so setup remembers the 2.0.x choice.
  - `CloseApplications=yes` with the default filter closes a running 2.0.x or 3.x app before setup touches its files.
  - The app icon is the 2.0.x `icon.ico`, moved into the UI project and set as `ApplicationIcon`. The script points
    `SetupIconFile` at it and `UninstallDisplayIcon` at the exe. Shortcuts take the exe's icon. The window icon is not
    set: that is feature work.
  - Setup excludes `*.pdb` (only the native SkiaSharp and HarfBuzz pdbs exist; `DebugType None`,
    `Directory.Build.props:28-31`) and `SpectrumVisualizer.*.xml` (the doc files exist only to unlock IDE0005,
    `Directory.Build.props:17-20`). The `de/` satellite of `RJCP.Core.Environment` ships.
  - Setup languages are Russian and English, Russian first, as in SemiPlot; Inno picks one from the Windows UI
    language.
  - `PrivilegesRequired=admin` for Program Files. `[Run]` uses `runasoriginaluser`, so the first start writes data and
    logs into the operator's `%LOCALAPPDATA%`, not the admin's.
  - The installer file name stays `SpectrumVisualizerInstaller.exe`, the 2.0.4 release asset name.
  - The publisher and URL stay `Semiteq, Inc.` and `semiteq.ru`, as in 2.0.4.
  - Uninstall leaves `%LOCALAPPDATA%\SpectrumVisualizer`: setup runs as admin and cannot reach each operator's
    profile. The app wipes its spectra at start; the README tells the operator how to remove the folder.
  - The version is `3.0.0` in `Directory.Build.props`, the single source. The workflow does not pass `-p:Version`;
    it fails when the tag version differs from the props version. This differs from SemiPlot, which keeps `0.0.0`
    and takes the version from the tag. The props comment carries no literal `Version` element, so the workflow's
    `sed` reads exactly one value.
  - The workflow triggers on tags matching `v[0-9]+.[0-9]+.[0-9]+` only. It fetches the tags again and fails on a
    lightweight tag: the release body is the tag annotation.
  - The workflow installs Inno Setup 7 with winget, pinned to `JRSoftware.InnoSetup.7` 7.1.1, and finds `ISCC.exe`
    under either Program Files folder. A dropped winget manifest fails the run loudly; the pin is bumped then.
  - The script uses only directives that Inno Setup 6.7 also accepts, so the local ISCC 6 compile is a real check.
  - The release-notes draft is in this plan, in Russian: the release bodies of v2.0.2 to v2.0.4 are Russian, and the
    writing-style rule follows the previous release. Section names are Russian, as SemiPlot's `### Новое`.
  - The release notes carry one bullet per PR with a bare `#N`. The PR numbers exist only after the merges, so the
    draft holds `#PR` placeholders the owner replaces; the trend bullet also names issue `#3`.
  - Operator texts (README, release notes, remedy texts) never point at OptoskyProj: the repository is private and
    its links give a 404. The firmware for this release is "the board firmware delivered with this release", which
    Semiteq hands out together with the installer. OptoskyProj#20 stays in `docs/architecture` as the protocol source.
  - The README stays English, as the repository's other documents. It names controls by their English text and says
    that a Russian Windows shows the Russian text.
  - The root `.editorconfig` stays: it still governs the text files outside `SpectrumVisualizer/` (workflows, the
    installer script, docs).
  - CI keeps one Windows job: the app ships for Windows only.

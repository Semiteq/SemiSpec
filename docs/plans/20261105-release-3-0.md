# Release 3.0.0

## Overview
- Ship the new app as version 3.0.0. An Inno Setup 7 script installs the self-contained win-x64 publish folder over a
  2.0.4 install, in place, with the same `AppId`, and removes the 2.0.4 files the new folder does not overwrite.
- A release workflow on a `vX.Y.Z` tag builds, tests, publishes, builds the installer and attaches it to a GitHub
  release whose body is the tag annotation. The workflow is written and statically checked here; it never runs in
  this slice.
- The version is 3.0.0 in `SpectrumVisualizer/Directory.Build.props`.
- The old WinForms app, its MSTest project, `SpectrumVisualizer.sln` and the old installer script are deleted; CI,
  `CLAUDE.md`, the README and `docs/architecture` lose every mention of them.
- Firmware compatibility: the app reads only the OptoskyProj#20 frame, the 2.0.4 app cannot read it, and the frame has
  no version byte. The `BoardNotResponding` and `UnrecognisedData` remedy texts (English and Russian) name old board
  firmware as a cause, and the README and the release-notes draft say "flash the board firmware from the OptoskyProj
  release first, then install".
- The README is rewritten for operators: install, firmware compatibility, how to use, where data and logs live. The
  developer sections stay below them.
- Scope guard: no feature work. The run does not tag, publish or push. The untracked folders `ComPortPopulator/` and
  `SprctrumVisualizer/` on disk are not touched.

## Solution Overview
- **Packaging follows SemiPlot**: an Inno Setup script under `Installer/` with paths relative to the script, fed by
  the self-contained publish folder that `Directory.Build.props:33-38` already defines, and a release workflow shaped
  like SemiPlot's. The script keeps the 2.0.4 `AppId`, so Windows sees one product and setup upgrades in place.
- **Decisions:**
  - The `AppId` is the 2.0.4 one, `{02EA7FE7-4B06-4B9C-93ED-2B49AE013EAA}`. Setup reuses the previous folder and the
    previous desktop-task choice, and the uninstall entry stays one entry.
  - `[InstallDelete]` lists the measured 2.0.4 file set minus the two files the new folder overwrites, plus the
    `runtimes` folder and the 2.0.4 desktop shortcut. A wildcard wipe of `{app}` is rejected: the operator may have
    chosen a folder that holds other files.
  - The Start menu shortcut is `{autoprograms}\SpectrumVisualizer` with `DisableProgramGroupPage=yes`, the same path
    as the 2.0.4 shortcut, so the upgrade overwrites it. SemiPlot's `{group}` is not used. Shortcuts carry no
    parameters: the app has no launch keys. The task name `desktopicon` stays, so setup remembers the 2.0.4 choice.
  - The app icon is the 2.0.4 `icon.ico`, moved into the UI project and set as `ApplicationIcon`. The script points
    `SetupIconFile` at it and `UninstallDisplayIcon` at the exe. Shortcuts take the exe's icon. The window icon is not
    set: that is feature work.
  - Setup excludes `*.pdb` (only the native SkiaSharp and HarfBuzz pdbs exist; `DebugType None`,
    `Directory.Build.props:28-31`) and `SpectrumVisualizer.*.xml` (the doc files exist only to unlock IDE0005,
    `Directory.Build.props:17-20`). The `de/` satellite of `RJCP.Core.Environment` ships.
  - Setup languages are Russian and English, Russian first, as in SemiPlot; Inno picks one from the Windows UI
    language.
  - `PrivilegesRequired=admin` for Program Files. `[Run]` uses `runasoriginaluser`, so the first start writes data and
    logs into the operator's `%LOCALAPPDATA%`, not the admin's.
  - The installer file name stays `SpectrumVisualizerInstaller.exe`, the 2.0.4 release asset name.
  - The publisher and URL stay `Semiteq, Inc.` and `semiteq.ru`, as in 2.0.4.
  - Uninstall leaves `%LOCALAPPDATA%\SpectrumVisualizer`: setup runs as admin and cannot reach each operator's
    profile. The app wipes its spectra at start; the README tells the operator how to remove the folder.
  - The version is `3.0.0` in `Directory.Build.props`, the single source. The workflow does not pass `-p:Version`;
    it fails when the tag version differs from the props version. This differs from SemiPlot, which keeps `0.0.0`
    and takes the version from the tag.
  - The workflow triggers on tags matching `v[0-9]+.[0-9]+.[0-9]+` only, and it fails on a lightweight tag: the
    release body is the tag annotation.
  - The workflow installs Inno Setup 7 with winget, pinned to `JRSoftware.InnoSetup.7` 7.1.1, and finds `ISCC.exe`
    under either Program Files folder. A dropped winget manifest fails the run loudly; the pin is bumped then.
  - The script uses only directives that Inno Setup 6.7 also accepts, so the local ISCC 6 compile is a real check.
  - The release-notes draft is in this plan, in Russian: the previous releases and tag annotations are Russian, and
    the writing-style rule follows the previous release. Section names are Russian, as SemiPlot's `### Новое`.
  - The release-notes draft has bullets by effect for the operator. PR numbers do not exist yet; only the trend
    bullet carries `#3`.
  - The README stays English, as the repository's other documents. It names controls by their English text and says
    that a Russian Windows shows the Russian text.
  - The root `.editorconfig` stays: it still governs the text files outside `SpectrumVisualizer/` (workflows, the
    installer script, docs).
  - CI keeps one Windows job: the app ships for Windows only.
